does not run an executable, forward into original code, supply DRM machinery,
change the matching recipe/oracle or manufacture replacement providers.

## Complete included CODE field census and limited IAT identity test

The accepted archive is read through both indices. Every one of its 1,019
members and 12,946 exports must join the emitted union metadata. Its 36,839
actual fields are joined through physical section/symbol bijections and exact
selected roots: undefined fields require their accepted original obligations;
retained local fields remain explicit. All 442 actual entry fields and the
single original host field are also included. This is a complete ordinary CODE
input census, not an assertion that every lazy archive member will be selected.
Native import support members are separately retained in the accepted partial
manifest; they are library candidates, not additional selected game bodies.

The twenty-five original IAT pointer proposals are independently gated by cell.
Every included use of that exact canonical name must retain DIR32, zero addend,
the original cell's role/base/target and its accepted IAT classification. CODE
uses additionally retain the accepted import ID and per-root original binding
row references, stored once per root and referenced by group key from each field.
The accepted original import catalog rejoins that cell to its
actual DLL/export identity; the partial manifest already binds the exact native
library, member and pointer export. This reuses accepted field witnesses; it
does not replay the original PE or full binding-detail scan.

A cell with any missing, changed or conflicting use receives no alias, while
other fully proved cells remain usable. Enabled `/ALTERNATENAME` directives map
only canonical pointer cells to actual `__imp_` pointer symbols. They are a
LINK-only identity experiment. They do not redirect to code symbols, approve
source calling conventions or adopt runtime providers. No CRT alias is added.

## One normal LINK, full diagnostics, no execution

The planned LINK uses `/MACHINE:X86 /SUBSYSTEM:WINDOWS /INCREMENTAL:NO`, normal
LIBCMT/OLDNAMES defaults, explicit VC/SDK library search paths, `/OPT:REF`,
`/OPT:NOICF` and `/VERBOSE:LIB`. It specifies no custom entry, forced duplicate
handling, ignored errors, missing-symbol waiver or whole-archive extraction.
All current CODE member default-library directives must remain exactly the
accepted LIBCMT and OLDNAMES requests. Default-library shadowing in the new
working directory or earlier VC/SDK path fails preparation.

The four pinned LIB files are selected diagnostic candidates. They do not
constitute a complete transitive default-library or OS/tool-loader closure.
Additional searched/loaded libraries remain unbound observations requiring
review; this operation does not grant link-provenance or game CRT approval.
File bindings preserve both requested paths and resolved physical identities,
so changing a logical path's destination or replacing its file fails rechecks.

After source review, a Python-only preparation can use:

```powershell
python tools/rebuild/application_link_diagnostic.py --source-sha256 <reviewed-tool-hash> --out <new-private-directory>
```

Only a separate root-authorized operation may add `--link-once`. That command
prepares and performs exactly one shell-free native LINK with a 180-second
timeout, hidden process window, cleared injected compiler/linker options and
explicit LIB paths. An append-only fsynced progress journal records start/end;
raw stdout and stderr are retained separately without truncation. No compiler,
LIB generator, game binary or output executable is invoked. Native timeout or
failure retains its evidence and requires reconciliation before another attempt.

Every LNK error/warning line, including repeated errors and unknown CRT/native
symbols, survives in the receipt. Canonical names join exact component/member,
root, physical/serialized field and original target metadata through the shared
provenance dictionary; repeated errors retain keys rather than duplicate entire
field lists. Raw library search,
found, referenced and loaded lines are retained as observations. Old LINK may
omit loaded-member rows, so the tool does not claim complete extraction from a
missing log channel. Duplicate/support-member behavior remains visible.

Nonzero return is classified as expected unresolved only when every error/fatal
LINK diagnostic is an unresolved-symbol diagnostic. Warnings are retained and
counted separately; a mixed unresolved/infrastructure failure remains an error
requiring review. Unexpected LINK success is
explicitly labelled unapproved and never causes execution or a runtime-ready
claim. Any produced EXE/map remains private evidence. CRT state, initializers,
TLS, resources, ABI, data/provider ownership and application behavior remain
unproved regardless of the linker's outcome.
