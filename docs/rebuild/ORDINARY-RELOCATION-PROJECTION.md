# Ordinary CODE relocation projection

`ordinary_relocation_projection.py` is a separate pure consumer for one selected
ordinary CODE root with complete relocation evidence. It writes no files and
invokes no compiler, native tool, linker or executable. Its operational factory
remains separately reviewed and authorized.

The caller supplies original COFF bytes, the complete authenticated central
contract and bare ordinary certificate, the exact ten-field selected physical
root, an authenticated original selected-provider map, and the combined export
census of every accepted CODE pool. The caller must authenticate all these
inputs and preserve their hashes. Export census completeness cannot be inferred
from a Python collection; it is an operational responsibility. A competing
logical export always blocks the root.

The consumer freshly replays the complete frozen ordinary observer. Its graph
must be complete and positive, with no missing fields or parent EH. It then uses
the unchanged unresolved-pool field classifier. Only that classifier's old
recipe screening observations for unreachable SafeSEH, weak records and their
auxiliaries can be discharged by the independently proved omission layer.
Every other field, namespace, type, association or policy blocker remains.
The original global recipe policy is unchanged.

Every field is an exact own-recipe DIR32 or REL32 record with original physical
symbol index, contained four-byte geometry, matching original operand target,
complete row hash and a replayed role/base/final/addend observation. Selected
CODE references require an unambiguous exact function entry and original
physical provider identity. Unselected executable references retain unresolved
CODE identities. Ordinary DATA, authentic IAT cells and explicit CRT contracts
retain separate unresolved identities; no data owner, import implementation,
CRT provider, ABI or lifetime is adopted. Nonzero DATA and CRT addends remain
unchanged. CODE interior targets remain unsupported.

The approved retained section, symbol and auxiliary-slot scopes must exactly
equal the frozen classifier's extraction plan. Numeric-index-preserving
namespace and serialization helpers remain unchanged. Output payload and
addend bytes must equal the original, every relocation must still reference the
same original physical symbol through its explicit bijection, and only the
selected canonical CODE root is exported. Defined references into omitted
sections become zero-valued undefined records only when both frozen proofs
approve that exact conversion.

Duplicate canonical definition/reference groups remain blocked in version 1.
A reference certificate argument is rejected rather than treated as a waiver.
Future integration must use the existing reviewed CODE-only V2 certificate on
its exact compatible scope. No TLS, unknown EH or LABEL storage-class exception
is introduced here. A union cannot borrow singleton omission decisions.

The receipt supplies original/output hashes, complete field proof hashes,
namespace bindings, comparison bases, undefined obligations and physical maps.
The operational factory must still perform unchanged-oracle MATCH on the exact
original and projected member, independent reparsing and recovered archive
verification, both existing export-ledger checks, durable exclusive publication
and resource/input stability gates. Pure source tests establish none of these
actual artifact outcomes. All runtime and provider flags remain false.

`assess_member` provides a structured eligible/blocked plan before serialization.
It catches only the dedicated `UnsupportedRoot` policy subtype. Unsupported
ordinary field TYPE/class, CODE interiors and uncertified namespace groups can
be quarantined per root with exact contract/certificate bindings. All source,
object, physical schema, full replay, original operand and authenticated owner
contradictions still raise fatal integrity errors. Every field's integrity is
checked before any field-policy quarantine, so an unsupported first field cannot
conceal a corrupt later field. Serialization errors remain fatal. Assessment
results authorize no output and are never accepted as proof inputs to
`project_member`, which independently repeats the complete classification.
