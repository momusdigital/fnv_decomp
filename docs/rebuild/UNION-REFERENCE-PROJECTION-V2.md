# Operational union reference projection V2

This new driver connects the accepted V2 code-reference proof to actual immutable source-built COFF objects. It leaves the main entry, original bulk producer, serializers, oracle and accepted archives unchanged. Source and synthetic tests are ready for independent review; no operational driver observation or emission has been performed.

The completed saved-metadata observation reconciled all 410 blocked recipe unions and 3,913 owners against all 68,657 selected owners. Its 185 candidate recipes contain 1,372 roots, 219,493 code bytes and 7,065 fields. These are candidates awaiting native shape certification and fresh comparison, not an unlock quota. The other 225 recipes and 2,541 roots remain blocked. Existing 12,946 emitted owners, 51,798 historically blocked owners, 88 missing-field identities, 95 local EH notes and optional-index absence remain explicit.

## Inputs and operational gates

`tools/rebuild/union_reference_projection_v2.py` consumes the exact ten input identities pinned by `union_reference_groups_v2.py`, plus the accepted saved-metadata receipt and compressed details. The new policy pins the sixteen invoked producers and dependencies, including the old comparison, span, strict COFF and entry mapping readers. No old producer is edited or patched. All four owned files are bound by the independent operational phase review; callers cannot replace the policy by changing its command-line hash alone.

The review record has schema version 1, kind `union-reference-operational-phase-review-v2`, approved status, reviewer attribution, explicit root authorization, exact owned source hashes and producer hashes, the saved observation/detail hashes and exact recipe list. `allowed_operations` names an exact `collect-box2089` or `project-box2089` phase. Native tools and executable linking must both be false. Root must separately authorize the actual phase. This source document and offline tests provide no such authorization.

The command requires `--policy`, `--policy-sha256`, `--inputs`, `--review`, `--review-sha256`, `--operation`, `--profile`, `--out` and `--authorize-coff-read`. Inputs JSON contains the ten exact V2 keys plus `metadata_observation` and `metadata_details`. Project mode additionally requires `--authorize-private-emission` and `--reference` with the exact owned image hash pinned by the policy. Collect mode rejects a reference image. Actual private paths belong in private phase records, not this document.

The all185 operational mode is deliberately unavailable in this version. Its source gate will be extended only after the real Box projection, independent output reconciliation, native link and authored typed caller artifacts exist. That delta must hash-bind and verify the actual receipt, member/archive/certificate, exact source/object identities, native outcome and independent reviews across the whole operation. Same addresses and success booleans do not suffice. No such artifacts or contract exist yet; the finite185 metadata observation remains usable as planning evidence only.

## Exact projection contract

The metadata loader rechecks the complete original ledgers and whole selected-provider map. After the operational gate, the driver hashes only the specifically authorized source/object paths from the immutable manifest, then reads one bounded object. V2 recomputes each individual root assessment and the whole union from actual COFF and complete pinned field proofs. The synthetic core's caller-supplied provenance is not operational authority.

Only plain external CODE records of type 32 with zero-addend DIR32/REL32 fields and an exact unique selected provider are supported. Groups may contain original undefined records or exactly one retained selected definition plus undefined records. Different targets, roles, ambiguous aliases, weak/common symbols, multiple definitions and data/IAT/interior groups remain rejected by the accepted core. Original source names do not identify providers.

The separate guarded name applier preserves every retained primary/auxiliary physical slot and its serialized bijection. It never coalesces records or retargets a relocation. The frozen namespace writer's duplicate restriction remains unchanged. The final definition-name set must equal the selected root exports plus explicitly approved retained literal definitions, where present; unrelated definitions remain rejected.

Project mode runs unchanged body/relocation comparison before projection and after independent staged COFF parsing. Every mapped section, payload hash, flags, primary/auxiliary record and relocation is compared through the separately pinned strict reader. The current reader intentionally rejects associative section auxiliaries; it does not extend EH support. A spool is streamed into bounded archive shards using unchanged bulk helpers; both linker indices and each recovered payload are verified, then the recovered member is independently checked against the original object and exact maps. No native archive utility runs.

Large historical streams and all observed native inputs are hashed before and after the complete operation. Small producer/review/source controls are rehashed per recipe; the current source/object is also rehashed after its comparison. This avoids rereading all historical streams and prior objects 185 times. Current optional-index absence is checked throughout. A native object or projected member is limited to 16 MiB. Archive recovery reads one verified member at a time rather than loading the shard. Output is exclusive under the private rebuild directory; existing or uncertain output is never resumed or overwritten.

Receipts distinguish source-hash attempts, native access attempts, successfully read byte counts, certification completion, projection attempts and completed projections. Errors preserve these facts and possible partial-output uncertainty. Final protected-input stability is checked even after a recipe failure. Journals and per-recipe certificate records are flushed as work completes; all flags for runtime, ABI, provider selection, native tools and executable linking remain false. Complete coverage records retain upstream status and exact upstream row identity rather than replacing the baseline.

## First real component and later finite recovery

The first authorized candidate is recipe 2089, with reset at `0x00db0920` (50 bytes), insertion at `0x00db0960` (72 bytes) and lookup at `0x00db09b0` (60 bytes). Its 182 source-built code bytes contain one intra-union REL32 reference and no selected external code, data, IAT, CRT or TLS field obligation. This offers a real definition-plus-reference linker mechanism test.

After source review, root may authorize exact COFF collection and then private component emission. Independent output reconciliation must precede native conformance/link permission. A later original authored caller should use the full declared types and naturally compiled thiscall methods, with separately typed reset storage and insertion storage. It should test reset state, insertion/lookup, duplicates, capacity, counts, boundary keys and guarded storage, using valid four-byte key buffers. No fake body, dummy class layout, fastcall register substitute, assembly or original-address fallback is permitted. Link and execution remain separate permissions; this driver provides neither.

Once the actual Box mechanism and caller contract pass their own reviews, a narrow source-reviewed artifact-binding delta can enable the finite all185 phase for separate root authorization. All 1,372 roots must independently pass actual source/object/proof, native COFF, field, namespace and unchanged comparison gates. A failure stops the phase and preserves outputs rather than weakening policy or manufacturing a recovered count. The original 12,946-owner pool remains an immutable separate lane until a reviewed consumer explicitly combines manifests.

Alternate runtime overlay inputs are excluded. They require a new explicit policy, fresh physical/root/provider proof and separate lineage; replacing old hashes or certificates is forbidden.

## Verification

The new offline suite uses authored synthetic COFF only. It covers positive native-shape collection, mixed definition/reference projection, strict staged/recovered map comparisons, streamed recovery, exclusive output, wrong/stale review scope, missing opt-ins, stale source/object/producer/index state, bounded payloads, partial-access failure facts and complete baseline coverage. Existing V2 synthetic tests continue to cover all whole-union identity and omission negatives. No real object, reference image, compiler, native utility or executable is accessed by these tests.
