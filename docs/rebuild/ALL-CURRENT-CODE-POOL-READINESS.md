## Expected finite operations

One process, one serial recipe pipeline and one append-only spool; no compiler,
model/GPU request, service mutation, executable linker or code execution:

1. Pin exact global inputs/producers/reference and preserve the current four
   source/test/policy/doc files in a new exclusive output's snapshots.
2. Consume the saved complete metadata universe in authoritative 2,988-recipe
   order, all 490,713 ordinary binding rows and 88 missing rows, and the complete
   owner stream. Retain all historical blocker/EH identities.
3. Open only the 1,429 named candidate-containing objects for fresh requested
   observation. Hash-check each requested source/object before use and again
   at final stability verification; hashing is additional file I/O, not another
   object discovery scan. The 1,428 distinct source groups retain variants.
4. Freshly reassess every requested root and compare its complete public row
   and binding ordinals/hashes with the saved inventory. An eligibility/proof
   mismatch stops globally. Recompute each whole-recipe union independently.
5. For eligible unions, run ordinary original-object comparisons, serialize
   once into the verified spool member, independently reparse COFF, then run
   rewritten comparisons. At most 1,429 before and 1,429 after comparator calls,
   covering at most 16,859 rows in each pass. Quarantined union roots do not
   receive a false fresh-MATCH claim.
6. Verify the complete spool ledger, plan deterministic shards, stream them,
   and independently walk every recovered member and both export-only indices.
   Recheck all observed inputs/index state before issuing the final receipt.

The frozen verification helpers intentionally perform extra in-memory reparses;
this is not a one-parser-call claim. The owned reference is 16,549,704 bytes and
is loaded once. The saved compressed inventory/binding/owner inputs total
117,619,987 bytes and are hashed/streamed/rehashed. The pilot's full historical
coverage gzip was 8,497,180 bytes. These measured input/output sizes inform a
budget, not a claimed all-current runtime or peak-memory measurement.

| --- | --- |

| Archive engineering ceilings | 60,000 members or 1 GiB per shard |
| Archive format ceilings | At most 65,535 indexed members; checked 32-bit offsets/counts |
| Inventory row length | At most 8 MiB |
| Binding stream / recipe buffer | Existing reader bounds: 1,000,000 rows total, 150,000 rows per recipe, 256 KiB per row |
| Object/member source identities | Exact named hashes; no truncation, fillers or substitute objects |
| Output reuse | New exclusive directory/files; no automatic resume or replay |

The member count cannot reach the archive ordinal limit in this population:
there are at most 1,429 members. Exact bytes still determine shard cuts.
One shard is plausible at this scale, but no exact shard count or emitted
member count is claimed before union serialization. The unconditional safe
count bound is 0–1,429 shards with whole-member cuts; the actual spool/export
ledger fixes the exact count. A member exceeding the format/engineering ceiling
causes a safe global failure rather than an unauthorized split or truncation.

**Not implemented in the frozen producer:** wall-clock timeout, process-memory
quota, disk/free-space quota, an operator stop-file, or a cumulative spool-byte
cap. Its one-object/one-union pipeline is a memory strategy, not a measured hard
memory limit. Neither 24 synthetic tests nor the pilot measured a full-scale
peak. The driver has no built-in cooperative cancellation/checkpoint-resume API.
Do not describe missing controls as existing flags.

Proposed first-run supervision contract, requiring separate source review before
root go:

- Launch the exact frozen CLI once with `--mode all-current`, under a small
  private supervisor that does **no COFF/namespace/selection work**. It must
  neither catch-and-continue source errors nor retry a terminated worker.
- Hard wall-clock deadline: **1,800 seconds**. Track only the owned child process
  and terminate/wait for that process on timeout or explicit operator stop.
- Memory abort thresholds: **1.5 GiB working set** or **2 GiB private committed**.
  A sampled monitor is explicitly a sampled abort, not a hard OS quota. If a
  hard limit is required, use a separately reviewed Windows job-object limit;
  do not claim that an ordinary timer enforces it.
- Proposed spool abort: **128 MiB**; complete new-output abort: **512 MiB**;
  require at least **2 GiB free** before starting and stop below **1 GiB free**.
  These conservative operation budgets are not new function-size or format
  eligibility limits. Any threshold hit yields an aborted/incomplete attempt
  for reconciliation, never a silently omitted owner.
- Poll at **two-second** intervals, using only the owned process and exact
  new output/spool/coverage/union/journal/snapshot paths. Any shallow check of
  shard files must remain confined to this new output directory; no old archive,
  work, local or checkpoint-store scan. Document possible between-poll overshoot.
- Preserve exact supervisor source/command/limits, child status and the last
  durable progress/spool ledger in new private logs. A supervisor success receipt
  must bind the child receipt and artifact hashes. If the supervisor aborts,
  consumers reject the run even if a late child file happens to exist.

This wrapper is a remaining small operational dependency, **not implemented by
this readiness document**. It avoids changing or duplicating the proven bulk

supervision arrangement can supply these controls, but an unsupervised run is

## Abort, quarantine and success semantics

Unchanged v1 rules deliberately favor whole-recipe quarantine:

- Fresh individual status must equal the saved candidate observation. Hash,
  input/proof/index changes, before/after MATCH failure, malformed maps/fields,
  spool corruption and inconsistent global exports stop the whole attempt.
- Distinct-record duplicate names, unsupported mixed groups or union association
  issues produce `BLOCKED_UNION` for every requested root in that recipe. No
  supplied certificate can enable the frozen consumer. There is no automatic
  root-closure or single-main projection unlock.
- Verified spooled members from unaffected recipes may form a partial archive
  set. The final child receipt is `incomplete` unless every requested root is
  emitted. All 68,657 rows remain accounted; historical blocked rows remain
  historical, and no `CANDIDATE_NOT_REQUESTED` row is expected in all-current mode.
- Coverage `EMITTED` rows are provisional until a final matching receipt and
  shard set exist. A failure after spooling/shard writing can leave such rows
  and partial files; file existence or an unfinished ledger is not acceptance.
  Preserve the failure; do not truncate or automatically replay the spool.

A full success requires 16,859 emitted code owners, all 56,492 retained code
relocations verified, both scalar literal owners exactly once and 16,861 unique
exports. Partial success must state the smaller actual counts and every union
blocker; it is not all-current completion. Unknown union-conflict counts are a
legitimate result of the authorized attempt, not permission to broaden the
policy until a target count is reached.
