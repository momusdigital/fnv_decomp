# Expanded diagnostic selection

This operational source lane builds on the separately accepted pure cohort
adapters and read-only observation. The old V4 diagnostic and helpers remain
unchanged. The observation proves 14,330 disjoint candidate Game-function
providers and 44,364 actual fields, including 7,082 supplemental fields and 399
IAT fields. It does not establish linker selection or runtime readiness.

The next proposed selected cohort adds the 1,372-reference, eight-generic and
two-overlay archives to the existing baseline and real host/entry. Its two DATA
predecessors are replaced by the accepted header-only `.rdata` successors;
payloads, aliases, flags and relocations remain unchanged. No whole-DATA arena,
blocked provider bridge or fabricated provider is selected.

The raw IOTask EH component remains a reviewed candidate, deferred from this
link because its separate logical demand has no included use. Its physical
export is not renamed or bound automatically, and unused handler/CRT obligations
are not forced into the diagnostic. A future actual consumer needs its own
identity and complete-use contract.

The KERNEL32 replacement must contain exactly the prior seven export identities
plus the original catalog's InterlockedDecrement cell, import ID 102. The old
seven-export library is replaced rather than accompanied. Other import libraries
remain unchanged. Exact native member/index/pointer identities are reobserved;
old proposals are rebound only to the new native member offsets for the same
exports. All 26 canonical pointer cells retain independent full-cohort use gates.
Hints remain metadata, unknown schemas fail, and no CRT alias is introduced.

The operational assembler awaits accepted native-conformance and new-import
receipts. Required conformance covers all three new CODE archives and all three
raw objects (EH and both DATA successors), even though EH is deferred. The
diagnostic LINK requires independent source/input review, root go and a separate
CPU lease. It uses the established normal SP1 startup and unresolved-error
diagnostic policy. There is no `/FORCE`, ignored unresolved, custom entry or
executable launch.

The runner's default operation is Python-only preparation. Its input request
contains exactly four scoped, hash-bound records: accepted supplemental native
conformance, new KERNEL32 library, its native receipt and its generation request.
Paths must remain in
the private rebuild root. The original observation and V4 receipts, all their
physical input bindings, the current source/helper/test/document hashes and the
new request are checked before response publication and again before LINK.
The native receipt must report successful generation of that exact library,
the exact generation-request hash and matching source identities, stable inputs,
the prior seven preserved identities and false ABI/provider/execution flags.
Its declared members and index must equal the actual library reparse. Failed,
unrelated or stale receipts are rejected. This joins independently reviewed
evidence rather than accepting an arbitrary JSON object. Actual eight-export
identity proofs are additionally rederived from the library bytes.

```powershell
python tools/rebuild/application_link_cohort_runner.py --source-sha256 <reviewed-tool-hash> --inputs <reviewed-input-request.json> --inputs-sha256 <trusted-request-hash> --out <new-private-directory>
```

Only a separately root-authorized, leased operation may add `--link-once`.
It delegates exactly one normal native LINK to the frozen diagnostic runner,
retaining its error classification, raw logs and no-execution contract. The
input request is a concrete component list, not a provider/runtime approval.
Unknown or missing conformance, stale inputs and source drift stop preparation.
