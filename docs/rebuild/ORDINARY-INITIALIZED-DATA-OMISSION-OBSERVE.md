# Finite initialized-data witness observation

`ordinary_initialized_data_omission_observe.py` is a separate operational wrapper
for the accepted finite census of 79 existing central views across 26 original
object identities. It reads the eight exact central metadata artifacts and the
accepted manifests; it never searches object directories or old binding streams.
It invokes no image reader, compiler, native tool, linker or game process.

The operational review kind is
`ordinary-initialized-data-omission-observation-review-v1`. Its exact file hash is
provided by the caller. The review binds the source/test/document freeze,
producer pins, accepted central receipt and exact census, independent source and
typed-witness review, and existing delegated root authorization. Native tools
and emission must be disabled. An optional composer is usable only with its
exact source hash and independent acceptance in that same operational review;
there is no arbitrary plugin import or fallback implementation.

The wrapper verifies all 303 central metadata record identities while retaining
only the 79 selected contexts. Each selected view has its exact original
contract, bare frozen certificate, record hash and requested physical roots.
The complete retained MATCH proof, authoritative recipes and selected native
owners must agree with that source/object/recipe lineage. Original reference
identity and image-check/tool fingerprints are authenticated through the saved
retained proof; this operation does not reopen the reference image or claim a
new byte comparison.

Only the 26 exact manifest objects and their exact source files are eligible
for reading. Each native object is materialized once per recipe, hashed, and
reused in memory across that recipe's singleton and union views. The accepted
typed-witness helper replays each view independently; it may parse the cached
bytes again. Original object files are not copied into output. Final input
stability rehashes the exact files, including those objects.

An optional reviewed composer receives those same cached bytes, the unchanged
contract and original certificate, and the real typed witness. The wrapper
stores each witness and optional composition with its hash. It does not turn a
typed witness into a provider choice or serialization gate. Type-zero COFF DATA
records do not establish source-level array or initializer ownership. Every
original blocker not discharged by the typed witness remains explicit.

Output must be a new exclusive directory under the ignored rebuild output
root. Its source snapshots contain only the authored wrapper source, tests,
documentation and typed-witness helper. Results contain metadata rather than
native payloads. Practical sampled bounds are 15 minutes, one GiB peak process
memory, and 128 MiB output. The external coordinator still owns the project's
CPU/metadata leases; the wrapper does not acquire or expand its own slot.

The durable progress journal is closed before terminal receipt publication.
The pending receipt is exclusively written and hard-linked atomically to its
terminal name. Input and resource checks run before and after publication; a
failed postpublication gate retracts only the wrapper's own newly published
terminal link. An abort retains its exact state and partial private evidence,
without a success receipt or automatic retry.

Authored tests cover real synthetic witness production, exact source/schema
review, the fixed 303-to-79 metadata selection, changed identities and foreign
paths, the optional fixed composer boundary, stale objects/certificates, source
drift, exclusive terminal publication and postpublication retraction. They read
no original object or reference image.
