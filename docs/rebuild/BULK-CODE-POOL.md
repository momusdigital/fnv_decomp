# Bulk CODE producer and reviewed six-root pilot

`tools/rebuild/bulk_code_pool.py` implements the reviewed
[bulk proposal](BULK-CODE-POOL-PROPOSAL.md) as new additive source. It imports the
completed writer/parser/inventory without modifying them. At accepted source
freeze v2 it had performed synthetic work only. The subsequently authorized
six-root Python pilot and native read-only inspection passed independent
reviews, as recorded below. No all-current production or game execution has
occurred. Separate root authorization remains required for any further phase.
Source compilation, an executable link and runtime provider adoption are not
implemented.

## Whole-recipe unions and unsupported name groups

`plan_union` freshly assesses each root and then recomputes retained sections,
symbols, direct fields and associations over the entire root set. It does not
combine one-root conversion/drop lists blindly. A definition that is retained
by another root remains a definition. Shared physical references retain one
record; STATIC labels keep their exact local offsets. Only complete approved
literal owners can add data sections, once per physical owner. Equal bytes in
different literal owners retain different names/identities. All source
placeholder storage stays omitted; a supported referenced definition converts
explicitly to zero-section/zero-value EXTERNAL with unchanged addend bits.

The name-only phase preserves every numeric index, auxiliary/payload/relocation
byte and field addend. Physical definition/local names derive from recipe,
original object hash and original symbol index. The selection phase uses the
frozen serializer and independently verifies section, primary and auxiliary
bijections, conversions, COMDAT/checksum/alignment and relocation target maps.
Output exports must equal exactly the retained real EXTERNAL definitions.
Every source section/primary/auxiliary slot has a disposition. The separate
strict inventory reader checks emitted metadata and section auxiliaries before
the unchanged oracle compares each requested root.

Unsupported EH/associations, weak/common/SafeSEH or unknown directives keep the
unchanged baseline policy. Only the exact original LIBCMT/OLDNAMES directive
sequence is retained per recipe; it does not adopt a CRT. A new root-closure
certificate does not automatically broaden this producer's population.

Different physical records needing one destination name are **not silently
coalesced**. `MIXED_DEFINITION_REFERENCE_GROUP_UNSUPPORTED` blocks any retained
definition plus separate references to that identity. All-undefined groups also
remain blocked in this implementation: **v1 has no certificate consumer**.
The operational review gate rejects a nonempty certificate input list, and the
pure union API records `CERTIFICATE_CONSUMPTION_FUTURE_SCOPE` if one is supplied.
No supplied certificate or approval flag can waive individual candidate checks.

**Remaining dependency:** the separate producer's existing contract covers one
root, CODE-only, zero-addend REL32 uses. Its full retained section set includes
directives and is distinct from its runtime/code set; its root identity schema
also differs from this producer's selected-symbol record. More fundamentally,
one-root duplicate names are blocked by the historical candidate policy, while
a cross-root collision cannot use a one-root certificate. Guessing dictionary
shape fixes would not make a valid integration. The unreachable partial
integration was removed after source review. A future reviewed producer and
consumer must prove the exact same root set, full/runtime sections, original
symbol provenance, namespace and all bijections without expanding the baseline
candidate set. Until then such groups return `REFERENCE_CERTIFICATE_REQUIRED`.
Data/IAT equivalence, conversion/group combinations and mixed def/ref are not
enabled. The six-root pilot shares an existing physical IAT record and needs
no distinct-record certificate. All-current production may remain incomplete;
this source does not claim that dependency is solved.

## One spool, deterministic shards and exports-only indices

One verified member per recipe is appended to an exclusive private byte spool
and fsynced member ledger. Each record carries offset/length/hash, recipe,
exports and complete union-metadata digest. The member's detailed receipt
retains source/compiler/flags, root set, exact binding references, maps,
namespace, obligations and before/after comparison results. An uncommitted tail
is rejected; no resume, truncation or uncertain replay happens automatically.

The archive producer streams those member ranges, preserving their hashes.
It creates two standard COFF linker members and a long-name table with exact
offsets, one-based second-index ordinals and even-byte padding. Linker indices
contain **defined public exports only**; undefineds remain in object symbol
tables and a separate obligation ledger. Exports must be unique globally,
including across shards.

Default shards end only between whole recipes at 60,000 members or 1 GiB,
also enforcing actual 65,535 indexed-member, 32-bit offset/count and COFF
limits. An indivisible oversized member blocks rather than being truncated.
Planning uses deterministic recipe order. A separate streaming walker reparses
both archive indices, recovers every member/hash/export set and holds only
one member object at a time. Synthetic small archives are byte-identical to
the previously accepted in-memory writer. Native Microsoft readability for a
future multi-root/sharded output remains an artifact-specific explicit check,
not an inference from synthetic tests. The measured read-only inspection below
covers only the actual six-root pilot shard.

## Operational gate, private outputs and failure contract

The CLI requires exact input paths, mode, fresh private output directory and a
hash-bound review JSON. It must record `phase` equal to
`bulk-code-pool-pilot-emission` or `bulk-code-pool-all-current-emission`, matching
`mode`, `approved=true`, `independent_source_schema_review_pass=true`,
`root_authorized=true`, the exact proposal hash and `source_sha256` covering
exactly the four new owned source/test/doc/policy files. This records a phase
decision; it is not an authentication mechanism. No such real emission gate
had been exercised at source freeze v2. The later pilot-only gate is recorded
below; the all-current gate has not been exercised.

New private output includes fsynced `progress.jsonl`, exact source snapshots,
`members.spool`, `members.jsonl`, compressed complete coverage and union records,
zero or more `code-pool-NNNN.lib` shards and a final receipt. Every owner has a
status and exact historical inventory row identity; baseline blocker sets stay
visible. All shared inputs plus requested source/objects and optional-index
state are rechecked before the receipt. Hash/proof changes are global failures;
unsupported unions remain explicit incomplete results. A failed run retains
new evidence and never overwrites an existing output. Partial files or a
progress journal are not complete artifacts; consumers require matching final
receipt/coverage/member/archive hashes. No native tool is invoked automatically.
