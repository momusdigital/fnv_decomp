# Field-bearing ordinary CODE factory

`tools/rebuild/ordinary_relocation_factory.py` is a new bounded operational
consumer of the independently reviewed pure relocation core. The accepted
eight-root zero-relocation producer and its outputs remain unchanged.

Version 1 accepts exact finite requests in the existing ten-field physical-root
schema. It consumes only actual **bare positive** ordinary singleton certificates
from the accepted central observation. A typed DATA or local-label composition
that discharges blockers is a different authority: this version does not import
it, turn its false base certificate into a positive certificate, or consume its
witnesses. Such roots remain blocked until a separately reviewed adapter exists.
The root observer, unresolved-field classifier and minimal COFF writer remain
frozen. No original source, object, archive or comparison gate is modified.

The complete selected physical-provider map is a namespace identity ledger,
not a list of materialized or adopted providers. Its accepted artifact contains
all 68,657 selected owners, source/object provenance, checked native sections and
extents, physical primary indices and planned canonical names. The factory pins
the exact map and independent outcome review, its five authoritative input
hashes and the historical producer snapshot. That map was produced by version
`0e2f3ec9...`; the current composer source has a separate reviewed successor.
The factory does not import or re-execute the current composer. It validates
every expanded entry against selected manifest/v3 facts, then passes only the
strict `(recipe_id, object_sha256, symbol_index)` identities to the pure core.
It does not reread either original global owner or binding stream.

Before opening a requested native object, the factory verifies the three exact
prepared CODE pools and independently accepted metadata: 12,946 original
exports, 1,372 supplemental union exports and eight ordinary leaf exports.
All 14,326 names must be unique. The corresponding three coverage streams join
by exact original address, physical identity, original row ordinal and hash;
the first-eight annotation must preserve its original row exactly. All 68,657
owners and the three prepared partitions are checked. An already prepared
logical CODE owner cannot be replaced, merged or selected again. This exclusion
check does not adopt the three archives into an application manifest.

Each request must match an authenticated central singleton and the selected
native/v3 proof. Its exact source and original manifest object are freshly
hashed. A candidate is freshly parsed and the pure core replays the complete
ordinary omission observation and frozen field classification. Missing fields,
actual parent EH, TLS, unknown roles/directives, unsupported storage and unknown
associations are not waived. Selected CODE references use their exact original
physical owner; unselected executable references and unowned DATA, IAT cells and
explicit CRT contracts retain their correctly typed undefined canonical names.
No stub, placeholder data, original-address fallback or automatic provider/ABI
adoption is produced. Base identities and original signed addends remain
distinct; code interiors are not silently promoted to callable entry points.

The core exposes a metadata assessment that catches only its dedicated
`UnsupportedRoot` policy exception. Integrity validation covers every field
before policy quarantine, so an unsupported first field cannot hide corrupt
later evidence. Hash, schema, full-replay, original-operand, provider-map and
serialization contradictions remain fatal. Distinct-record namespace groups
are unsupported in this first relocation consumer; an unrelated certificate
cannot waive them. A future CODE-only V2 grouping integration needs its own
compatible contract and review.

An eligible assessment is not a serialization capability. The actual projection
independently repeats all checks, preserves numeric indices during name-only
binding, then emits explicit section/primary/auxiliary bijections with the
unchanged writer. Payload bytes, field addend bits, relocation kinds and targets,
section flags, COMDAT and exact directive semantics must remain unchanged.
The independent second reader checks every staged and recovered COFF member.
Both archive linker indices contain only defined exports; undefined obligations
stay in member receipts rather than being advertised as archive providers.

The unchanged ordinary comparator runs on the exact original object before
projection and on the staged member afterward. It receives the final canonical
names and their **base** address view, preserving signed field addends. Every
comparison must be MATCH with the original full extent, no errors or byte
differences and every relocation matching. The loaded owned reference buffer
must have the exact expected digest before the unchanged image probes. Any
comparison failure aborts the attempt; it is not an eligibility quarantine.
Recovered archive members must be byte-identical and independently reparsed.

Output requires a new exclusive private directory. Source snapshots and fsynced
progress precede member work. Limits remain sampled peak memory 1 GiB, elapsed
15 minutes and private output 128 MiB, with individual native objects bounded to
16 MiB. These are sampled checks, not OS hard quotas or a runtime guarantee.
Terminal publication reuses the reviewed zero-relocation producer's atomic
publisher: the terminal journal is durable and closed before the exclusive
success receipt appears; failed post-publication stability removes only the
owned success name and retains failure evidence. There is no automatic retry.

The mandatory independent operational review receipt binds the exact source
freeze, pure core and dependencies, request, actual central evidence, accepted
complete map and its outcome review, and all prepared exclusion artifacts.
It records root's delegated bounded-production authority honestly; source/test
acceptance alone is not an actual operation. Native tools, executable linking
and game/member execution remain disabled. Runtime/provider/ABI flags stay
false. Complete successor coverage preserves the original assessment and all
prepared upstream partitions, adds only this operation's status, and records
unsupported requests explicitly without claiming fresh body comparisons.
