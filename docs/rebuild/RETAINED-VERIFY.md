# Verify existing retained objects

`tools/rebuild/verify_objects.py` compares the existing hash-identified COFF files in a retained builder manifest against the owned reference image. It does **not compile**, replace objects, rewrite recipes, link or execute game code. This is different evidence from a successful `build_and_match.py` run, which compiles fresh temporary objects. A newly compiled source baseline cannot attest that an earlier retained object has those same bytes.

## Unchanged comparison gates

The verifier directly calls the existing `build_and_match` module's imported `Coff`, `Pe` and `compare` functions, `image_ok`, `recipe_names`, `eh_sections` and `eh_tails`. It uses the exact function manifest fields supplied by the original `check_unit`, full authoritative recipes for `recipe_names`, and the same conditional `FunctionSpans.from_index` behavior as original `main`. The only replaced operation is compilation: the actual retained object is loaded and hash-checked instead. None of the original comparison code, masking rules, function-size checks, relocation handling, image probes or EH inference logic is copied or modified.

`build/function_index.json` is absent in the current checkout. Original `main` explicitly passes `spans=None` in that case. The retained receipt records `function_index_present=false` and a null index hash, rather than claiming canonical-index span enforcement. Normal compiled-function extent, recipe-size, byte and relocation comparisons still run. Where the index exists, the unchanged `FunctionSpans` validation is used and its hash recorded; a test proves a conflicting span fails. Index presence/content must remain stable during verification. This is an existing oracle limitation, not evidence that a canonical index has been reconstructed.

The retained gate additionally requires every selected unit status to be `ok`, all function and byte counts to match, no listed EH-tail mismatch, no conflicting inferred EH binding and stable inputs. These fail-closed checks prevent a zero-function comparison error or inference conflict from being obscured by equal aggregate counts. Global EH consistency is calculated across the selected scope with the unchanged `eh_tails`; partial scope cannot establish consistency with excluded units.

Local EH diagnostics and global coverage are reported separately, preserving original oracle semantics: its documented `eh_tails` rule accepts a listed tail when any valid matching unit covers its bytes. A local placement/relocation diagnostic may coexist with globally covered listed tails. `function_byte_verification_pass`, `global_listed_eh_coverage_pass` and `original_oracle_parity_pass` expose those checks; `strict_local_eh_diagnostics_pass` records the stronger zero-diagnostic condition. Successful retained comparison with local notes is explicitly `pass_with_diagnostics`, never an unqualified runtime EH-provider claim. `runtime_closure_verified` is always false. Before retaining a particular provider's EH sections, review that provider's local evidence and complete section closure even when global listed coverage passes.

## Inputs, scope and receipt

Example command shape, with separately obtained private paths and exact hashes:

```text
python tools/rebuild/verify_objects.py --manifest <retained-manifest.json> --manifest-sha256 <hash> --image <owned-reference-image> --image-sha256 <hash> --out <new-private-receipt.json> --jobs 2 --require-full
```

`--recipes` defaults to `build/units.json`; `--root` defaults to this checkout. Jobs are limited to one or two parsers. No compiler process is started. Authoritative recipe reconciliation validates the stored recipe, compiler/flags, original recipe index, recipe identity and manifest recipe hash. Every manifest row must be compiled, refer to a distinct object path, and have matching actual object/source hashes. Current source files are observations only: this does not independently prove compiler causality, transitive-header identity or reproducible toolchain inputs.

Default scope is all manifest recipes. `--only` and `--limit` can select a smaller scope; partial manifests can be inspected but are explicitly recorded as partial. `--require-full` rejects any omission relative to the authoritative recipe. No absent unit or function is silently counted as checked. An image SHA-256 must be supplied explicitly, and the existing image fingerprint gate must also pass. The image loaded into memory must have that hash.

The new output path must not exist. Receipts contain no game bytes or raw byte-difference records; mismatches retain only addresses, counts and ordinary comparator error descriptions. The compact JSON records:

- `kind="fnv-retained-object-verification"`, schema 1, pass/fail and an explicit no-compilation verification description.
- Exact authoritative/manifest/selected scope, selected recipe indices and `full_authoritative`.
- SHA-256 identities for the retained manifest, authoritative recipes, complete reference image, optional span index, image-probe specification and actual comparison/helper/verifier source files.
- Per-unit recipe identity/index/hash, actual object hash, recorded/current source hash, selected/matched function and byte counts, comparison status and compact EH placement/inference evidence. Each actually matched function also records symbol, original address, size, native section/value and `verdict="match"`; provider consumers must check this identity rather than relying on object-wide counts.
- Overall function/byte/EH counts, tail mismatches, inferred-binding conflicts, image-probe results and input stability.

Before issuing a receipt, the verifier rehashes all observed objects, source files, manifests, image, available index and tools. Existing evidence and receipts are not overwritten. A failed output write removes only the new incomplete receipt created by that operation. A power failure can still leave an incomplete file; consumers must parse and hash the complete receipt, verify its pass/scope/input identities, and match each provider to its exact object/recipe row before using it as evidence. A self-reported boolean from a different object or compilation is insufficient.

Receipt eligibility also remains narrower than linker eligibility: only selected recipe functions and documented same-object aliases covered by the comparison can gain checked-body evidence. A metadata-bound definition not listed as a selected function, data layout, initializer order, COMDAT selection or calling convention does not become verified simply because another function in its object passed. Canonical planning remains separate and must retain those distinctions.

## Tests and native result

Twelve original synthetic tests cover real comparison of synthetic COFF/PE payloads, changed object hashes, changed bytes even after updating an object's declared hash, stale image hashes, the original image-gate rejection, changed recipe/source observations, partial/full scope, inference conflicts, canonical span enforcement, absent-index reporting, parser concurrency limits, immutable receipts, zero-function comparison failures and explicit global-coverage/local-diagnostic separation. The synthetic tests replace the unrelated game image-probe result and use small controlled EH returns where needed; native verification uses the real image gate and unchanged comparator/EH functions.

The first full native receipt, private `build/rebuild/retained-verify-full.json`, is preserved as a **failed stricter zero-local-diagnostic experiment**: all 2,988 unit comparisons, 68,667 function rows and 1,954 listed EH tails matched, with zero inferred conflicts, but 95 local EH diagnostics across 16 units. Root and independent validation reviewed the unchanged original global gate before authorizing explicit dual reporting; those diagnostics are retained rather than erased.

The immutable `build/rebuild/retained-verify-full-v2.json` reports `pass_with_diagnostics`: all 2,988 existing objects, 68,667 function rows / 11,458,254 function bytes, and 1,954 listed EH tails / 138,526 bytes matched. All three requested function/global-EH/original-parity flags and retained verification are true, inferred conflicts are zero, and inputs remained stable. Strict local EH diagnostics are false (the same 95 notes across 16 units); runtime closure is false. All 16 image probes passed, and the optional function index was absent. The receipt binds the updated verifier and unchanged original core sources; independent validation checked its flags/hashes before any conditional game-leaf probe was authorized. Any selected provider's EH/runtime closure still needs its own review. The earlier full source oracle and narrow allocator rename proof remain separate evidence. This verification is additional private rebuild evidence, not a new official service upload, standalone game link or gameplay result.

The final producer/consumer contract adds exact per-function matched/native-entry rows, rather than promoting providers from aggregate counts. Immutable `build/rebuild/retained-verify-full-v3.json` reran the same complete comparison with 68,667 such records; all counts, 95 diagnostics, pass/strict flags and original core inputs agree with v2. Its SHA-256 is `04d44b73e81982f846bfe8d81806db72ea669586b579ff22007dfd6f7d831297`. Independent validation reviewed that final scope and leaf entry before the narrowly scoped [game leaf probe](GAME-LEAF-PROBE.md). V1 and v2 receipts remain preserved historical evidence, not overwritten attestations.
