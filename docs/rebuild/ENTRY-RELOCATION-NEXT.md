# Next entry-reachable relocation repairs

The next concrete proposal covers 19 further missing fields in ten selected
owners across six complete translation units. Ten fields install dispatch-shaped
headers using existing data carriers; nine store existing free-function
addresses. This document and the separate declarative proposal authorize no
native compile, projection, provider selection or executable. The accepted
two-source repair tool, tests, policy and result document remain frozen.

## Original census and bounded evidence

The original entry graph still records 47 missing fields in 27 owners. The
global original audit still records 88 missing fields. Three reachable fields
already have separate accepted compile-only overlay observations: the earlier
`0x00aa0fc0` pilot and the new `0x0084ba20` / `0x00c033c0` pair. Those new

This proposal reads the exact existing entry derivation and source triage,

rescan objects. Each proposed tuple joins the same recipe, selected owner,
original field, native section/offset and entry binding ordinal/hash. The
earlier HIGHLOW/source evidence remains historical until an actual future
compile operation freshly checks the original site and operand.

## Separate runtime-overlay manifest contract

Both entry projection and bulk CODE owners require a separate versioned
alternate-object lane. The current all-current producer consumes original
retained proofs only and excludes the original missing-field owners. Its busy
run and accepted original entry projection must stay unchanged. No proposed
overlay automatically unlocks those consumers.

The next implementation should produce a private
`fnv-runtime-source-overlay-manifest` with a new schema version and these
separate hash-bound records:

1. **Original ancestry.** Original recipe index/id and exact recipe hash;
   original full source/header hashes, retained object/manifest/v3 proof hashes;
   original selected owner, function symbol/address/size/native span; and the
   original binding, relocation-audit and missing-field identities. These remain
   historical original provenance, never the purported source of a new object.
2. **Actual overlay build.** Frozen transformation policy/tool hashes, every
   exact guarded edit, generated TU hash, source/header include origins, compiler
   binary/code-generator/header hashes, unchanged flags and explicit context
   adaptations, new object hash, durable operation identity and full comparison
   receipt. Include complete exact recipe row multiplicities and fresh ordinary
   MATCH verdicts; preserve existing local EH notes and unapproved EH states.
3. **Fresh native identities.** New complete COFF symbol/auxiliary/section/
   COMDAT/relocation observations, exact source-root extents and selected span
   coverage. Every physical field, target symbol index, kind, signed addend,
   original target/base and alias has a new binding row and canonical record
   hash. Defined code targets, undefined carriers, section symbols and aliases
   retain their physical distinctions. No old symbol index or old object proof
   may be relabeled as a new physical observation.
4. **Migration proof.** An exact original-to-overlay field map with the two
   respective object hashes, source proofs and physical identities; old
   HIGHLOW/operand confirmation, new DIR32/zero-addend/exact target proof, equal
   non-field bytes and unchanged other references. Re-audit all original missing
   fields in every replacement owner, including explicitly unresolved fields,
   and census every additional field. Record original missing count and
   candidate-specific missing-after count separately. Reject unintended new
   references, stale fields or incomplete coverage.
5. **Explicit alternate selection.** A new runtime-only replacement selection
   names each accepted alternate owner by original symbolic function address,
   original selection hash and fresh overlay definition identity. Other same-TU
   functions are checked comparison coverage, not automatically adopted runtime
   providers. Distinct original and alternate source/object/provider namespaces
   persist. No original source hash is assigned to generated source.
6. **Consumer gates.** Fresh binding/root-closure and any canonical-reference
   group certificates must consume the alternate lane and its complete proof.
   Current canonical CODE identity includes `(recipe_id, object_sha256,
   physical_symbol_index)`; the new object therefore has a distinct identity
   even when its original symbolic address matches. A reviewed consumer must
   explicitly select that alternate, retain field provenance and recompute
   namespaces, aliases, span/auxiliary/SafeSEH/EH decisions and projection oracle
   comparisons. Original certificates are not reusable as fresh overlay proof.

The two already accepted repair receipts demonstrate only their bounded
compile/geometry/comparison results. Their existing saved inputs are enough for
later readers to derive fresh metadata, but their receipts do not themselves
contain this complete alternate-lane contract. A new read-only manifest/binding
derivation may cite them unchanged; it must not amend or impersonate those
original build operations. If needed evidence is missing, report that gap rather
than claim it was recorded. Runtime/provider/link/execution states stay false.

using the 19 exact proposal records. Pin the bounded include closures and exact
