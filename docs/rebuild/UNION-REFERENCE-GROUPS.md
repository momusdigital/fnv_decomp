## Two precise group kinds

`tools/rebuild/union_reference_groups_v2.py` is a new versioned implementation.
Its saved-metadata assessor checks complete whole-union field hashes and scopes,
all namespace duplicate indices and exact selected provider identities. The
native-byte core, used only with authored synthetic objects at this stage,
recomputes the frozen bulk planner over the **whole requested root set**. No
union of individual drop lists or boolean eligibility waiver is accepted.

1. **All original undefined.** Every distinct member must remain ordinary
   EXTERNAL, section/value zero, type 32, auxiliary-free, and outside IAT/data/
   TLS/EH/common/weak/interior domains. Every member needs an actual retained
   field. Every group field must have exact original selected-entry resolution,
   one provider at offset zero, zero addend and supported DIR32/REL32 geometry.
2. **One selected definition and original undefined references.** Exactly one
   member is the selected provider's real retained root entry in this same
   recipe/object, value zero, EXTERNAL function/type 32 and auxiliary-free. All
   other members satisfy the undefined rule above. The retained definition must
   match the selected provider's exact physical identity and original address.
   Two retained strong definitions, even at equal bytes/offsets, are rejected.

Names and type metadata alone do not prove provider ABI or object lifetime.
The proof joins immutable provider identity, all original field targets/bases,
complete field hashes and physical records. Type fields are preserved, not
rewritten into a claimed C++ signature. Unknown/interior/IAT/data/common/weak,
nonzero-addend and omitted-definition conversion groups remain blocked in this
version. Nonduplicate existing obligations retain their original dispositions.

## Certificate and guarded consumer

Certificates bind the exact full root set, object/source identity, original
union-plan digest, complete field-proof digest, every group, full namespace,
section/primary/auxiliary maps and explicit provenance. Persisted JSON map keys
are normalized without losing indices, and colliding integer/string keys are
rejected. This avoids treating a JSON ordering difference as a semantic remap.

Both group kinds retain every original physical record and its distinct
serialized mapping. No coalescing or relocation retargeting is permitted.
The new name-only applier recomputes the exact certificate first, rejects hidden
duplicates, updates only named primary Name fields/string-table extent and
checks every unaffected byte, section and symbol fact. The frozen v1 namespace
and bulk producers retain their original duplicate rejection. The pure v2
serializer requires exact maps and original-symbol relocation targets, preserves
payloads/addends and rejects duplicate strong exports. There is no disk/native
emission driver at this stage.

Before any actual subset, the consumer must bind the accepted production
receipt/union/coverage, retained manifest/proof/selection, original binding
stream and selected provider inventory; reconstruct all requested contracts and
their full retained-field order; and verify fresh native symbol/auxiliary facts
for only the separately authorized exact subset. All-current metadata planning
must retain existing 12,946 emitted and 51,798 historical-blocked dispositions,
classify all 3,913 remaining owners and preserve the original 95 EH notes,
optional-index absence, 88 missing identities and false runtime/provider states.

## Source implementation and review gate

Fifteen authored synthetic tests pass for both group kinds, preserved indices,
unchanged v1 rejection, persisted JSON maps, complete root/field coverage,
role/base/provider/interior/operand failures, native weak/common/definition/type
shape failures, duplicate strong definitions, stale/forged certificates,
serialized payload mutation, pre-proved unrelated literal exports and exact
export-name rejection. They also check policy/pin consistency, bounded skipping
of large irrelevant emitted records, missing input sets and current-index/
producer rejection before metadata decoding. No test opens a Game object/image
or invokes a native process.

`load_saved_metadata` is a metadata-only evidence collector for later separately
authorized source planning or exact-subset consumption. It pins and rechecks
the complete ten-input basis, four frozen producers, loaded module locations,
its own implementation and current optional-index absence. It validates the
original 68,657-owner coverage, 410 blocked recipe sets and 3,913 owner identities;
joins exact historical inventory row ordinals/digests; builds an unambiguous
selected-provider index; and reconstructs all requested original field contracts
in the whole-union root order. It preserves 95 retained local EH notes, strict
local-EH false and all 88 original missing identities. It opens no native object,
image or source body. The caller receives complete contracts, provider evidence
and explicit provenance; arbitrary caller-supplied provenance in the pure core
is not operational authority.

The collector can restrict its returned metadata to an exact recipe subset but
still verifies the full historical source streams. Its summary distinguishes
requested, metadata-candidate, still-blocked and unassessed roots. It never
changes the historical selected set or relabels a candidate as emitted. The
pure namespace/serialization APIs recompute the original frozen whole-union
plan, then every V2 group and map, before transforming authored input bytes.
There is no CLI/disk emission driver. A future exact-subset wrapper must bind
this accepted source, the collected provenance and current native source/object
hashes, require separate root authorization, and perform fresh original/source
comparisons plus independent staged/recovered mapping checks.
