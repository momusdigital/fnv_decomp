## Separate guarded name-only applier

The existing `coff_code_archive.namespace` retains its global duplicate-name
rejection. A new versioned `guarded_namespace` applier permits exactly the
same-root, all-undefined CODE group certified by the accepted evidence. It
requires source indices 289 and 1392 to remain distinct, ordinary EXTERNAL
undefined zero-value, auxiliary-free records with compatible type status.
Their eight exact zero-addend REL32 fields must still reference the corresponding
original records. Both names point to selected original `0x0043d4d0`.

The applier rejects hidden duplicate indices, extra duplicate groups,
definitions/common/weak records, IAT/data role mixing, incompatible types,
different providers, nonzero addends and changed field geometry. It changes
only the eight-byte Name fields of specifically bound primary records and
extends the string table/length. It verifies every original section and symbol
fact after parsing, plus every original byte outside those permitted fields.
Appending two equal strings does not coalesce the physical records.

The unchanged serializer then applies the root certificate's exact section and
symbol selections, including explicit omitted-definition-to-undefined
conversions. Its complete primary and auxiliary maps must equal the accepted
reference certificate. In particular, physical 289 maps to planned serialized
index 9 and physical 1392 to 203. No relocation is redirected from either record
to the other. Unrelated code/data/EH/TLS sections and source definitions are not
retained by guessing. Expected undefined counts are 280 records and 279 names;
these do not imply providers exist.
