# Expanded diagnostic source-provider cohort

This separate source-only integration lane preserves the accepted V4 diagnostic
tool and receipts. It proposes a new private input ledger containing the existing
12,946-root baseline, actual application entry and host, plus the accepted 1,372
reference-union roots, eight generic roots, two overlay roots and one IOTask EH
component. No new executable link or execution has occurred in this lane.

`application_link_cohort.py` pins exact accepted artifacts and supplies strict
metadata adapters. Each projected field must join its original physical section
and symbol to the actual serialized record, relocation kind and addend. Duplicate
undefined records remain separate. The reference-union adapter verifies the exact
old union row and certificate without changing that row's historical eligibility.
Overlay providers preserve old logical caller names while recording their distinct
generated source-object identities. The EH adapter retains all eleven fields and
the exact local SafeSEH registry. It adds no CRT alias or frame/runtime approval.

Selected exports, logical physical owners and original function addresses are
three independent disjointness checks. Equal bytes, matching names or ordinary
lazy-archive behavior do not excuse a duplicate selected source provider. Import
support-member candidates retain their separate lazy-library semantics.
Baseline CODE participates through full provider records, not export strings;
its original addresses and logical physical owners are checked against every
new component. A relocated section without its own exact root is rejected;
there is no fallback attribution to an unrelated parent. EH physical field
duplicates fail before any dictionary can coalesce them.

Only the accepted raw DATA successors are candidates: their sole change is the
eight-byte `.data` to `.rdata` section-name field. All payloads, flags, geometry,
symbols, sixteen aliases and zero relocation state must remain unchanged. The
blocked whole-DATA provider bridge is excluded.

The IOTask object exports its physical source identity. Its separate logical CODE
demand remains unbound until an explicit reviewed integration contract and complete
included-use census justify any link-only identity binding. The old V4 cohort has
no use of that logical demand; it is not counted as an already resolved target.

The remaining InterlockedDecrement IAT cell is coordinated with the import owner.
A new eight-export KERNEL32 candidate is proposed to replace the selected old
seven-export library while preserving that artifact unchanged. The other three
libraries remain unchanged. Actual native member/index/pointer proof and every
included use of each affected canonical cell are prerequisites; DLL/export names
come only from the accepted original catalog.

Native read-only conformance is separately needed for the three new archives and
three raw objects (EH and two DATA successors). The gaps owner coordinates one
bounded batch with the dependency reviewer. The documentation coordinator alone
reserves shared CPU/meta leases; these tools do not mutate lease files. A fresh
diagnostic LINK needs the exact source and input reviews, native conformance and
root go, under the current lease caps. No fake provider, ignored unresolved,
`/FORCE`, custom entry or executable launch is part of this integration.

Current checkpoint: pure adapters and synthetic tests only. The operational cohort
assembler awaits the exact native-conformance and import-extension receipts. No
component is treated as ABI, provider or runtime ready by this ledger.
