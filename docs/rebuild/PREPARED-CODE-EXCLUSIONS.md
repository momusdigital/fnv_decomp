# Prepared CODE collision exclusions

This versioned metadata producer records exact accepted CODE namespaces before
another projection batch. It emits no object, archive or executable and makes
no provider or application-manifest selection. Prior producers and outputs stay
unchanged. Original game images and native source objects are not opened.
Exact already-prepared archives are fingerprinted, never parsed or copied.

The ordinary prepared epoch contains 14,329 distinct names: 12,946 baseline,
1,372 union-reference, eight zero-relocation and three relocation-bearing roots.
Accepted member ledgers, receipts, independent outcome reviews and the complete
68,657-owner planned identity map bind each name to its original selected
`(recipe_id, object_sha256, symbol_index)`. Cohort source hashes, record ordinals
and record hashes stay attached. A source hash from another cohort is not a
valid substitute. The complete map is namespace identity evidence, not a list
of adopted or materialized runtime providers.

Four broader application candidates are separate: one application-entry root,
two alternate-source overlays and one EH physical candidate. Overlay records
retain both actual alternate-object identity and original logical namespace
identity. The EH candidate retains only its own physical namespace; its
prospective old logical demand remains explicitly unbound. It cannot be
silently rewritten into a selected original provider.

All 14,333 prepared names are collision exclusions, with ordinary and broader
cohorts preserved separately. This is not a selected application input list.
The earlier application observation had 14,330 candidates and excluded the new
three-root ordinary pool. The subsequent V5 selected count of 14,329 describes
a different set from the ordinary prepared count of 14,329. Equal counts do not
prove equal sets. The manifest therefore supplies no selected-application count
and all application/runtime/provider/ABI adoption flags remain false.

The producer accepts only a hash-bound independent source/input review under
root's delegated metadata scope. It verifies the complete original selection,
manifest, retained proof and accepted planned map, including the map's
historical producer snapshot rather than the unrelated current composer file.
It reconstructs records from exact accepted member ledgers and the bounded
application observation; it does not treat every key of that observation's
mixed CODE/DATA namespace as a CODE export. Unknown cohorts, identity modes,
borrowed source hashes, duplicate names and altered logical/physical identity
relationships fail closed.

Output requires a new exclusive private directory. The manifest itself is
marked as requiring a successful producer receipt and independent outcome
review. Source snapshots and durable progress precede publication. All used
input/source/artifact hashes are checked before and after; optional index
absence is preserved. Sampled limits remain 1 GiB peak memory, 15 minutes and
128 MiB private output. The reviewed atomic receipt publisher closes the
terminal journal before exposing success and removes only its own success name
on a failed post-publication check. There is no automatic retry.

input. Actual manifest hashes and measured production status are recorded only
after the separate accepted metadata operation and independent outcome review.
