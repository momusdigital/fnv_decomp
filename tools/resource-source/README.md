# Resource source renderer

`resource_source.py` checks a small JSON declaration of Windows resources
against a strict schema and renders Windows resource-compiler (`.rc`) source
from it. It uses only the Python standard library (3.10 or newer).

**What the output does not show.** Rendering `.rc` source does not show:

- that a referenced file exists or is suitable;
- that icon 101 resolves at run time;
- that a resource compiler accepts the output;
- that any startup, runtime, ABI or provider obligation is met.

This tool is not the runtime-readiness checker, and it reports no readiness or
playability result.

| File | What it is |
|---|---|
| `resource_source.py` | Validator, renderer and command-line tool. |
| `examples/minimal.json` | The handoff's acceptance example: icon 101 only. |
| `examples/full.json` | A synthetic icon, manifest reference and VERSIONINFO. |

The tests are in `tests/resource-source/`.

## What it touches

The tool reads one file, the JSON manifest you name. With `render --out` it
writes one file, the `.rc` path you name. That is all the file access it does.

It never:

- opens, stats or lists any file named *inside* the manifest (icons, XML
  manifests or anything else);
- reads or writes `.res` or PE files;
- runs a compiler, linker or any other program;
- uses the network, a browser, a game installation or another application.

The manifest path and the output path must be local. UNC and device paths
(`\\server\share`, `//server`, `\\?\`, `\\.\`) and reserved device names (`NUL`,
`CON`, `COM1`, ...) are refused before any file access.

## Usage

```
python tools/resource-source/resource_source.py validate <manifest.json> [--format text|json]
python tools/resource-source/resource_source.py render <manifest.json> [--out <file.rc>] [--overwrite]
```

- **`validate`** prints a summary of the declared resources. It says whether
  ICON 101 is declared and lists what is not established. With
  `--format json`, the summary also reports `files_checked: false` and
  `compiler_run: false`.
- **`render`** writes the `.rc` source to stdout, or to `--out`. `--out` has
  these rules:
  - The name must end in `.rc`.
  - It creates new files exclusively. `--overwrite` replaces an existing regular file with an exclusively created sibling via atomic replacement; hardlinked peers keep their old contents.
  - It refuses links or reparse points in the input or output path, directories, and writing over the manifest.
  - It never creates directories.

| Exit code | Meaning |
|---|---|
| 0 | Manifest valid. The summary or `.rc` source was produced. |
| 1 | Manifest rejected. Nothing is rendered or written, and each problem is listed by its JSON pointer. |
| 2 | Usage or file error: bad arguments, a missing or unsafe manifest path, or a refused `--out`. |

Diagnostics:

- They name positions (`/resources/0/file`) and rules, but never repeat the
  rejected value.
- They never print the manifest or output path, or any absolute path.
- Argument errors never echo the arguments.

### Example

```
python tools/resource-source/resource_source.py render tools/resource-source/examples/minimal.json
```

This renders the following, with CRLF line endings:

```
// Generated by tools/resource-source/resource_source.py (fnv-resource-source-manifest v1).
// Rendered only from explicit caller declarations. Referenced files were not
// opened or checked: this source does not show that they exist, that a
// resource compiler accepts it, or that a program finds these resources.
// Declaration digest: sha256:4570ea57445bf17a327d9678f46f2b552ed558122e912b9d1c1de2adf4d5d54d

// No language declared: the resource compiler default applies.

101 ICON "assets/icon.ico"
```

## Schema: `fnv-resource-source-manifest`, version 1

The input is JSON, encoded as UTF-8 without a byte order mark. The rules:

- Unknown keys are rejected at every level.
- Duplicate JSON object keys are rejected.
- Numbers must be JSON integers. `true`, `1.0`, `"1"`, `NaN` and `Infinity`
  are not accepted as integers.

### Top level

| Key | Required | Value |
|---|---|---|
| `schema_version` | yes | The integer `1`. |
| `resources` | yes | A list of resource objects (0 to 256). An empty list renders no resources. |
| `schema` | no | If present, exactly `"fnv-resource-source-manifest"`. |
| `default_language` | no | A language used for every resource that does not declare its own. |

### Language

A language is written `{"primary": P, "sub": S}`:

- `P` is 0 to 1023 (0x3FF) and `S` is 0 to 63 (0x3F), the LANGID fields.
- It renders as `LANGUAGE 0xPPP, 0xSS`.
- `{"primary": 0, "sub": 0}` is an explicit neutral language. It is different
  from leaving the language out.

### Resources

Each resource has a `type` and an integer `id`:

- `type` is ASCII letters in any case. The case is folded only for ASCII, so
  `"Ä±con"` is rejected rather than folded into `ICON`.
- `id` is a JSON integer. String resource names are not supported.

| Type | Keys | Renders as |
|---|---|---|
| `ICON` | `type`, `id` (1 to 65535), `file` (ends in `.ico`), optional `language` | `101 ICON "assets/icon.ico"` |
| `MANIFEST` | `type`, `id` (1 to 16, the range Windows reserves for manifests), `file` (ends in `.manifest` or `.xml`), optional `language` | `1 24 "assets/app.manifest"` (24 is `RT_MANIFEST`) |
| `VERSIONINFO` | see below | a `VERSIONINFO` block |

No resource is ever added for you:

- An icon 101 appears only if you declare it. The startup source's lookup of
  icon 101 is evidence of a lookup, not of an icon, so the tool does not
  default to it.
- A manifest is always a reference to a file you name. The tool never writes
  XML or manifest settings.

### VERSIONINFO, a deliberately small subset

At most one `VERSIONINFO` resource is allowed per manifest.

| Key | Required | Value |
|---|---|---|
| `type`, `id` | yes | `"VERSIONINFO"` and 1 to 65535. |
| `file_version`, `product_version` | yes | A list of exactly 4 integers, each 0 to 65535. They render as `FILEVERSION a,b,c,d` and `PRODUCTVERSION a,b,c,d`. |
| `file_flags_mask`, `file_flags`, `file_os`, `file_type`, `file_subtype` | no | Integers from 0 to 0xFFFFFFFF, rendered as 8-digit hex. Each is rendered only if declared, so there are no defaults. |
| `language` | no | The resource language. |
| `string_table` | no | `{"language": <language>, "codepage": 1200 or 1252, "strings": {...}}` |

Conflict rules:

- `file_flags` needs an explicit `file_flags_mask`, and may not set bits
  outside it.
- If the strings include `FileVersion` or `ProductVersion`, it must equal the
  numeric version written as `a.b.c.d`.

String fields:

- `strings` must be non-empty.
- Names are case-sensitive and limited to `Comments`, `CompanyName`,
  `FileDescription`, `FileVersion`, `InternalName`, `LegalCopyright`,
  `LegalTrademarks`, `OriginalFilename`, `PrivateBuild`, `ProductName`,
  `ProductVersion` and `SpecialBuild`.
- They render in sorted order.

The string table's block name and the `VarFileInfo` `Translation` value are
derived only from the declared string-table language and codepage. For example,
language 9/1 with codepage 1200 gives block `"040904B0"` and Translation
`0x0409, 1200`.

Without a `string_table`, the block body is empty (`BEGIN`/`END`), and no
`StringFileInfo` or `VarFileInfo` is added.

### String value allowlist

Each value is 1 to 256 characters. The only characters allowed are ASCII
letters, digits, space and these: `. , _ ( ) : ; / & ' -`

Rejected:

- `//`;
- leading, trailing or doubled spaces;
- quotes, backslashes, `#`, `+`, `|`, `<`, `>`, `{`, `}`, `*`, `$`, `%`;
- control characters, line breaks and anything non-ASCII. Write `(c)`, not Â©.

No escape sequence such as `\0` is added.

## Identity, duplicates and defaults

A resource's identity is its normalized type, its id and its effective
language. The effective language is its own `language`, or else
`default_language`, or else none.

These are rejected:

- two resources with the same identity, including types that differ only in
  case (`icon` and `ICON`);
- two resources with the same type and id where one has no effective language.
  An unspecified language could become any language at compile time, so the
  pair is ambiguous;
- a second `VERSIONINFO`.

The same id is allowed under different types (ICON 1 and MANIFEST 1) and under
different explicit languages.

Defaults never leak in the output. In RC, a `LANGUAGE` statement applies to
every later resource. So resources with no effective language are rendered
first, before any `LANGUAGE` statement, under a comment saying the compiler's
own default applies. Every declared language then gets its own `LANGUAGE`
statement. `default_language` is the only default mechanism, and declaring it
twice is rejected as a duplicate JSON key. The string table's language is never
inherited and must be explicit.

## Relative path grammar (`file`)

The grammar is fixed and does not depend on the host operating system:

```
path    = segment *( "/" segment )            ; 1..8 segments, <= 200 characters
segment = first *rest                         ; 1..64 characters
first   = ALPHA / DIGIT / "_"
rest    = ALPHA / DIGIT / "_" / "-" / "."
```

The path is also rejected if any of these apply:

- it is empty;
- it is absolute (`/x`), UNC (`//x`), has a drive (`C:`, `c:x`), or contains
  any other `:` (for example an alternate stream);
- it contains a backslash (the only separator is `/`);
- it has an empty segment (leading, trailing or doubled `/`);
- it has a `.` or `..` segment, or contains `..` anywhere;
- a segment ends with `.`;
- a segment's base name is a Windows device name (`CON`, `PRN`, `AUX`, `NUL`,
  `COM0`-`COM9`, `LPT0`-`LPT9`, in any case);
- it contains a quote, a control character, a line break, a space or a
  non-ASCII character;
- it does not end with the extension the type requires.

Paths are emitted verbatim, with no normalization: case is kept and nothing is
resolved. A resource compiler resolves them relative to its own invocation,
which this tool does not control or check.

## Limits

| Limit | Value |
|---|---|
| Manifest size | 256 KiB |
| JSON nesting | 8 levels (the schema needs 5) |
| Resources | 256 |
| Path | 200 characters, 8 segments, 64 characters per segment |
| String value | 256 characters |
| Reported problems | first 50 |

## Determinism

The output is 7-bit ASCII with CRLF line endings, with no byte order mark and a
trailing CRLF. Resources are ordered like this:

1. Resources without a language come first.
2. The rest are grouped by language, in ascending (primary, sub) order.
3. Within each group the order is ICON, then MANIFEST, then VERSIONINFO, each
   by ascending id.

The header's declaration digest is the SHA-256 of the canonical, normalized
declaration.

These things do not change the output:

- the order of keys and of resources;
- JSON whitespace;
- the letter case of the type;
- whether a language comes from `default_language` or from the resource itself.

After rendering, a final check confirms every line is printable ASCII and that
no line is a preprocessor directive.
